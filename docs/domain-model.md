# Domain model

Status: Phase 2 read foundation. Existing storage remains lex.*; new namespaces reserve ownership without pretending future entities are implemented.

| Domain          | Entities and relationships                                                                    | Authority and boundary                                                                            | Implementation                                                                    |
| --------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Identity / core | User, Organization, Role, Permission, UserOrganization join                                   | Platform memberships govern authorization; external app user IDs require verified mappings        | JWT clients/roles exist; identity tables deferred                                 |
| Merchant        | Merchant has Stores; Customer references; Order has PickupRequests and one or more Shipments  | Commercial request ownership, not physical movement state                                         | Deferred; canonical merchant_id/order_id are null                                 |
| Shipment / core | Shipment has Packages, TrackingNumber, ShipmentStatus, ShipmentEvents, Origin and Destination | Platform shipment service is sole writer; LEX consumes and commands it                            | Existing service/table/history; additive canonical read model and identity view   |
| LEX             | Command, RoutingDecision, AssignmentDecision, Event, WebhookEvent, Retry, EngineVersion       | Owns orchestration/decisions, references shipment IDs                                             | Existing commands, matching rule, outbox/worker; decision entities deferred       |
| Carrier         | Carrier, CarrierProfile, Vehicle, Availability, Assignment, Trip, ProofOfDelivery             | Carrier identity/availability and responsibility; shipment transitions remain validated centrally | Existing carrier/capacity; standalone assignment/trip/acceptance deferred         |
| PUDO            | PUDOLocation, OperatingHours, Capacity, Pickup, Dropoff, Handover                             | Location operations and custody                                                                   | Deferred; at_node does not identify a PUDO location                               |
| Operations      | Incident, Alert, Exception, Escalation, OperatorAction                                        | NOC consumes platform truth; audited operator commands                                            | Existing exception transitions, health, replay; case-management entities deferred |
| Billing         | Rate, Quote, Charge, Payment, CarrierPayout, Invoice                                          | Financial interfaces; no payment execution                                                        | Existing wallet approval only                                                     |
| Audit           | AuditEvent, AccessLog, SystemEvent, Consent, DataRetentionRecord                              | Platform cross-system trace, minimal personal data                                                | Existing audit/history and request IDs; expanded context/retention deferred       |
| Integration     | Event, Receipt, Subscription, Delivery, Outbox                                                | Platform event routing and delivery bookkeeping                                                   | Existing outbox/destinations/deliveries; gateway receipts deferred                |

Order ≠ Shipment ≠ Assignment ≠ Trip. A match currently reserves carrier capacity and updates shipment state; it does not prove acceptance or movement. Do not create synthetic orders, trips or accepted assignments from a match.

Public IDs encode the full lowercase UUID without hyphens, e.g. SHP_550e8400e29b41d4a716446655440000. Internal UUIDs remain primary keys. Prefixes are reserved for all requested entities in src/domains/identifiers.ts; reserving a prefix does not implement that domain. External user IDs are not assumed to be UUIDs. Existing LEX-* tracking values remain unchanged. Views derive IDs for old and new rows without copied data or backfill downtime.
